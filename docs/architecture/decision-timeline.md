## Threads

- **Entry path:** APIM in front of three frontends (0008, 2026-09-06) became a BFF in front of the browser with APIM kept in front of service APIs (0013, 2026-10-26). Services still validate every token themselves.
- **Identity:** B2C to Entra (2026-09-11); a local mock issuer with browser login (2026-09-13); service callers added with client credentials (0018, accepted 2026-10-31); browser sessions with the tokens kept on the server (0019, 2026-11-02); a native sign-in for the Android app (0023, 2026-11-04). The DEV credential type is still open.
- **Frontend:** SPA (2026-09-13) replaced after six weeks by server-rendered Next.js (2026-10-26), with the older record kept; an Android client followed on the same BFF (0023).
- **Caching:** one server cache (0002) became three owned layers (0014); the catalog's listing cache is the first service use of the server layer (2026-11-07), with the Relay and HTTP layers recorded for the same path.
- **Real time:** the vendor queue polled (0012), then a push stream was layered on top with polling kept (0021, 2026-11-02); the customer's order status polls (`WI-CUST-010`).
- **Fulfillment:** the seam of 0001 (2026-09-04) became a running, separate consumer nine weeks later (`WI-ORD-003`, 2026-11-07), so "events only" holds in the running system and not only in the design.

Three things the phases show. The foundational build was delegated and the slice was interactive, and the controls grew between them (the handoff rules in September, the approval list and clean-agent checks in October). The plan's order held until a real run contradicted it (the issuer, the service mapping, the cold-start timing). And the plan's phase 4 and 5 items were done in the margins of the slice, not as phases, which is why the project plan reports several phases as partly done.
