# Backlog / Work Items

Work items follow the template in `docs/method/work-item-template.md`; statuses and notes are defined in `docs/method/status-and-supersession.md`. This folder holds them as markdown while the project is pre-Issue; each item is written to be copy-pasted directly into a GitHub Issue and added to the repo's Projects board when picked up — same pattern as `docs/governance/open-items-register.md`, but for planned work rather than deferred concerns.

**Start here:** `current-plan.md` (what is built and next), `STATUS.md` (the status of every item) and `epic-catalog.md` (the epics and their planned items across every hat). Two items are fully detailed now as validation examples of the template shape:

- `EPIC-CACHING.md` + `WI-CACHE-001.md` — Interface/Contract type, derived from ADR-0002
- `WI-NFR-001.md` — Document/Artifact type, derived from ADR-0002/0004/0005/0006 + vision

`PARKING-LOT.md` — transient, per-conversation open items not tied to a specific work item. Distinct from `docs/governance/open-items-register.md` (permanent tech debt/tradeoffs).

Once epics are picked up one at a time, their remaining work items get fully detailed here, following the same pattern.
