## What the session did

After the lead merged the open pull request, the branch was rebased onto `main`, and three items moved on. (1) The test-design review (register 178, resolved): the browser tests no longer break when seed data, mock fixtures or other tests are added. Real-stack tests bring the stock they take, and the croissant tests set and restore their own amount; no real-stack spec lists the whole seed; the mock-backed tests count from the mock's own fixture; the profile specs clean up after each test. The changed mock specs passed, and passed again with a listing added to the mock for the run; the real-stack smoke passed on a fresh stack. On the lead's confirmation the rule became working rule 6 in `docs/testing.md`, and the one finding left (the Android flows' shared stock) became register 200. (2) The one Dependabot alert left on `main` (register 199): `picomatch`, which has no fixed version, reached in the shipped mobile app only through its build tools. The lead left the alert open on GitHub; the local dependency audit accepts it until a set date, after which it fails again (checked both ways). (3) The chaos work item the lead asked about (`WI-CHAOS-005`) had already been built and merged the day before, so nothing was built for it; the lead marked it Done. The branch was pushed after the gates, the Linux .NET run and the secret scan, and again with the later work and this revision.

## Errors the assistant made, and what caught them

- The plan at the start of the session named `WI-CHAOS-005` as the next item to build; it had been built and merged the day before. Caught by the assistant on reading the specification, before any work started.
- An edit script was written through a shell heredoc, against the repository's rule that files are written with the Write tool (the same slip as the afternoon session): noticed by the assistant straight after; the later scripts were written with the Write tool.
- An edit script expected the wrong number of matches twice (five listing counts, not six; a second "1 item hidden." line): caught by the script's own check that each target occurs as often as expected, before the second file was written.
- The first usage record named a work item, which put the traceability table out of date: caught by the Node gates; the table was regenerated before the commit.
