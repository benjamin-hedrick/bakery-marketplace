## What the session did

The lead's second full dev deploy run stopped in the apply: Azure accepted the Container Apps environment's create and never finished it, and Terraform gave up after 30 minutes.

- **Read from the lead's sign-in (no value printed):**
  - The environment's own provisioning state was still `Waiting` 77 minutes after the create.
  - The state held 17 resources, without the environment.
  - Service Health listed no event.
- **The teardown:** the lead approved the destroy of the 17. Its emptiness check then failed, as expected, on the environment outside the state. The agent deleted the environment on the lead's approval; it took about 25 minutes. Afterwards the group and the state were checked empty, and the foundation untouched.
- **Changed:**
  - The environment's create limit is now 45 minutes, inside the job's 60.
  - The teardown runbook names the leftover.
  - Register 227 is new.
  - The evidence file `docs/evidence/WI-DEP-001/first-full-dev-runs-2026-11-20.md` is new.
  - Not run in Azure yet.
- **Branch cleanup:** four merged local branches and two merged remote branches were deleted, and local `main` was fast-forwarded.

## Errors the assistant made, and what caught them

Register 201, (31): the assistant told the lead that `git branch -d` would be a second check that the branches were merged. With rebase merges it cannot be, and it refused three merged branches (caught by its own output; checked again with `git cherry` before `-D`). Smaller, caught before the evidence was written: a draft runbook line said all 17 resources were destroyed before the state had been read; the state was then checked (0 managed resources).
