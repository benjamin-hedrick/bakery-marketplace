## What the session did

The lead set four goals in order: be ready to deploy and tear down dev (costs understood, no secret exposed), deploy and tear it down with evidence, perhaps repeat without the Redis costs, and design UAT/SIT and Prod without deploying them. This session did the first goal and the infrastructure half of the second.

- **Ready:** where secrets and private values live, and write-only Key Vault placeholders (register 214); the costs of the dev environment and a budget alert on its group; the foundation applied; the first real plan in the pipeline; the real apply stage (re-plan under the lock, refused unless it is the approved plan) and the real teardown (the destroy guard on a real plan, an emptiness check); an identity check; no Key Vault purge on destroy (register 108); token refresh for long runs.
- **Applied** on the third attempt: 26 resources in `rg-bakery-dev`, a re-plan with no changes, the state checked for secrets (`docs/evidence/WI-DEP-001/first-dev-apply-2026-11-20.md`). The first two attempts stopped on the identity check's own assumption, an empty Redis argument, and Cosmos being refused in East US; each was fixed, tested and recorded, and the failed Cosmos account was deleted with the lead's approval. Plans are now made from the state (register 213, the lead's decision).
- **Torn down** on the second attempt: all 26 destroyed, and the group, the foundation, the state and the soft-deleted vault checked afterwards (`docs/evidence/WI-DEP-001/first-dev-teardown-2026-11-20.md`). The destroy guard first refused the Key Vault secrets falsely (fixed, tested on the real plan reduced to what the guard reads; register 107 resolved), then the last check failed falsely because Azure still listed a just-deleted workspace (fixed with a retry, not yet run on Azure).

Not done: the images, the post-apply secret step, the app deploy and the smoke tests.

## Errors the assistant made, and what caught them

Register 201, (18) to (26). Two cost a pipeline run each and were caught by the run: the identity check assumed the deploy identity could read all of its own roles, and the Cosmos region was not checked before the first apply. One was caught by the provider reading back what it had applied: the empty Redis argument. Two were false failures of the assistant's own safety checks, caught by the teardown runs: the guard on the Key Vault secrets, and the emptiness check with no allowance for Azure's listing lag. One left a saved plan, with values in clear text, in the working tree for a few minutes (git-ignored, deleted, the script fixed). The rest were caught by the lead's questions or by reading the result: a register item that offered an option an ADR had already decided, an overstatement of what that ADR settled, and scripts written through a heredoc or in text mode against the repository's rules.

## How to read the numbers

- **Relative cost is a size, not a price.** 13.78 is one of the larger sessions: three apply attempts and two teardowns, each failure reproduced locally, fixed, tested and recorded, with the lead's approvals and pipeline runs between them..
- **Most of the elapsed time was the pipeline and Azure** (a destroy alone took about 23 minutes) and the lead's approvals; the screen's API time counts the assistant only.
- **No claim is made about value per unit of cost.** The human review time is not in these figures.
