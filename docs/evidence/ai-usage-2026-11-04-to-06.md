## What the sessions did

- **Mobile spike:** the Android toolchain and Maestro installed on the lead's machine, ADR-0023 (the mobile stack) written and accepted, the `WI-MOB-001` spec, a failing allergen journey test fixed after a pull request check, and a stalled pipeline job triaged (not reproduced, register 144).
- **Mobile build:** the shared `customer-core` package, the Expo Android app (sign-in with PKCE, menu, detail, cart, checkout, order status), its Maestro flows (four, then ten) with a one-command runner, the allergen work of `WI-MOB-002` with four seeded customers, the demo guide rewritten after a real run with nine screenshots, and the scripts index with its gate; the branch was pushed with 23 commits.
- **Sonar and docs:** the README, scope and roadmap refreshed and a local SonarQube scan script, run once (the quality gate passed; the ratings were poor and the 276 findings untriaged, register 153).
- **Register walk-through:** decisions on register items 131, 137, 150, 152, 118 to 122 and 132; the Sonar findings triaged and fixed; the cross-browser failures diagnosed.
- **Register items and `WI-ORD-010`:** register items 118, 120, 122 and 152 built in parallel; register 137 (per-client rate limits); `WI-ORD-010` (saved payment methods replacing a decline switch) in six layers, with 38 to 42 local commits.

## How to read the numbers

- **The mobile build's line counts disagree with git.** For that session git shows 10,439 insertions and 105 deletions over 140 files for 19 commits; the screen says 3,243 and 245. The screen does not say what it counts, and scripted edits are probably not in it. Neither is a measure of value.
- **The Sonar reading was taken before the last two replies**, so it understates that session slightly (a later reading is the $1.34 shown; the first was $1.15).
- **Several runs were lost to the assistant's own errors or to the machine**, which is in the cost: about eleven emulator runs and three demo starts in the mobile build (a wrong build path, an IPv6 address, a blocking process, a blind fallback tap, YAML with unquoted colons, a sold-out fixture, one run stopped for low memory, a Windows standby that stalled a flow for 29 minutes) and a real-stack smoke run stopped for low memory in the last session.
- **No claim is made about value per dollar.** The human decisions and review time are not in these figures.

## What this does not show

The decisions the lead made in these sessions (the mobile stack, an Android-only local-only app, seed data and not test hooks for test state, the register decisions); the review still to come on the token handling in the Android app and the security-adjacent changes; and the plan-limit readings, which are in the assistant's log but not here.
