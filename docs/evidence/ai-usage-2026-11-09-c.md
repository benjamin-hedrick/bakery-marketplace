## What the session did

It began with a question (are the chaos decorators in the README's test headline actually used?). The answer was no: one decorator existed and was used only by its own tests. The session then built the chaos work as a series of work items, each gated and committed: `WI-EVT-004` (a chaos event transport, also run around the real Redis Streams transport), a proposal and then ADR-0024 (Proposed) for seeded, configured fault injection at the interfaces the system already has, `WI-CHAOS-001` (scenario files, keyed decisions, a journal, a gate, a response indicator, the events and cache layers, one line in each C# service), a change to the dev Terraform so the .NET services run as Development through a per-environment variable, `WI-CHAOS-002` (the repository, broadcast, payment, catalog-gateway and notification-sender layers), and `WI-CHAOS-003` (the lost-response fault in five layers, a TypeScript package with the BFF's gate and client layers, and equivalence tests for the BFF and the Android app). It ended with a new open item the chaos layers produced (checkout answers a failing processor or store with a bare 500, register 170) and a second about retries that are not yet safe (register 171). The work is on `feature/chaos-event-transport`, committed locally and not pushed. Method: every test that asserts the system coped first asserts from the chaos journal that the fault happened, and each layer was mutation-checked (the injection was disabled on purpose and the matching tests had to fail); two weak tests were found that way.

## How to read the numbers

- **The screen's line count is not the repository's.** The screen counts 5,249 added and 92 removed; git shows 83 files changed, 4,585 insertions and 221 deletions over 8 commits from `origin/main` to the branch head (before this record). The two are counted differently; the screen also counts the edit scripts and test runs' scratch files.
- **Wall-clock time is mostly the lead reading and deciding.** API time is 38 minutes of 3 h 40 min. A large share of the session was design questions and decisions between builds, which are not API time.
- **No claim is made about value per dollar.** The human review time is not in these figures.
- **A caveat from the screen itself.** It attributed 82% of the last day's use to continuing in one context across different tasks, and 17% to the size of `CLAUDE.md` (about 5k tokens on every request).

## What this does not show

The decisions the lead made (where the scenario files live, an allow-list gate for local and dev only, the dev stack running as Development, a new ADR rather than an amendment, "build while deciding"), and what is still open: the whole-stack run with committed evidence, the Maestro flows that still stop the BFF, the web app's Relay equivalence test, the web proxies' gate, the two behaviours in register 170 and 171, and the review of ADR-0024 (Proposed).
