# Latency measurement (2026-11-09)

> **Status:** Snapshot · 2026-11-09 (UTC; the evening of 2026-11-08 locally), `scripts/dev/measure-latency.mjs` against the demo stack (`scripts/dev/demo.mjs`), Windows 11, Docker Desktop, Node 25.9.0, commit `4772c6e`. **Current result:** with the listing cache in its default in-process mode, the BFF listings query answers at p50 2.5 ms and p95 4.0 ms, the server-rendered home page at p50 7.5 ms, and warm checkouts at p50 69 ms; the first checkout after a stack start took 2.5 s. It repeats the measurement of [2026-10-30](latency-2026-10-30.md) after the listing cache ([WI-CAT-003](WI-CAT-003/after-2026-11-07.md)) and the review fixes.

## Method

The same as the 2026-10-30 record: one stack started once by `demo.mjs` (which seeds and warms reads only), then one run of the script. Requests are sequential from the same machine to the BFF (`:4100`) and the web server (`:3000`); no network is included. 50 rounds of three read requests, then 20 test orders (one Country Sourdough each, as Alice Customer, a new idempotency key each). The raw numbers are in the script's JSON output (`--json`), which is not committed.

## Reading it

- Reads match the cached figures of the listing-cache record (about 3 ms and about 8 ms at p50), against 26 to 33 ms and 32 to 42 ms uncached on 2026-10-30.
- Warm checkouts (69 ms p50) are unchanged from 2026-10-30 (63 to 69 ms): the cache does not touch the order path.
- The first checkout after a stack start is still slow (2.5 s here, 4.6 s on 2026-10-30; register item 98). One run, so whether the difference is real is not known.
- Not measured, as before: concurrency, throughput, a deployed network, the browser, the Cosmos emulator under load. One machine, one run: variation between machines or days is unknown.
