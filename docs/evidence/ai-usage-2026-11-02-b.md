## How to read the numbers

- **This session cost about 65% of session D (10.66)**, with 302.1k output tokens against 417.8k, and added fewer lines (3,462 against 6,992). It had no compaction and no cache miss.
- **Cache reads dominate the token counts** because each request resends the whole conversation from the prompt cache; the 87.9M figure does not drive the cost.
- **Lines added is not a quality or productivity measure.** It counts tests, documentation, generated files and evidence records as well as code. The screen reports 0 lines removed, which is not explained here.
- **No claim is made about value per unit of cost.** One session is not a sample, and the human review time is not in these figures.

## What this does not show

The human decisions in the session (the priorities and their order, the rate-limit design, the choice of the headers and limits to build now, which branches to combine); which problems the lead's questions found that the agent had not; the cost of the review that is still to come, because the lead has not yet reviewed this branch.
