## G-H02: mutation sample (10 tests, approved by the lead)

Method: one line of production code changed by hand, the test class run (`dotnet test --filter` or `node --test`), the named test checked for failure, the change restored. The tree was clean afterwards. A test is *killed* when the named test itself fails. The mutations are one sample, chosen by me, not a mutation-testing tool run.

| # | Test | Mutation | Result |
|---|---|---|---|
| 1 | `CheckoutServiceTests.TheClientNeverSuppliesAPriceAndEverythingIsRepricedFromTheCatalogNow` | Drop the modifier price deltas from the unit price | **Survived** (the named test uses a listing with no modifiers; other tests in the class failed) |
| 1b | same test | Add 1 cent to the computed unit price | Killed |
| 2 | `CheckoutServiceTests.RepeatingACheckoutReturnsTheOriginalOrderAndTouchesNothing` | Skip the existing-order lookup | Killed (also `TheSameKeyWithADifferentRequestIsRefused`) |
| 3 | `OrderCancellationTests.ACustomerCannotCancelOnceTheVendorHasStartedPreparing` | Allow a customer cancel from InPreparation | Killed (also the combinations theory) |
| 4 | `OrderLifecycleTests.CompletedAndCancelledAreFinal` | Let `Require` accept a Cancelled order | Killed (also the every-action-from-exactly-one-status theory) |
| 5 | `PickupScheduleTests.ASlotInsideTheLeadTimeIsNotOffered_AndOneExactlyAtItIs` | Lead time plus one minute | Killed |
| 6 | `StockReservationTests.OneLineWithoutStockRejectsTheWholeRequest_AndNothingChanges` | Reject only when no line is reservable (partial reservation) | Killed |
| 7 | `JwtValidationTests.ValidateToken_WrongIssuer_ThrowsException` | `ValidateIssuer = false` in `AuthServiceExtensions` | **Survived** (see below) |
| 8 | `ResourceOwnershipHandlerTests.MissingRoleClaim_FailsBeforeOwnershipCheckIsCalled` | Call the ownership checker before the role check | Killed |
| 9 | `cart.test.ts` "a quantity is capped at the per-order limit, and the caller is told it was capped" | Remove the per-order cap | Killed (also `setQuantity clamps between one and the limit`) |
| 10 | `place-order.test.ts` "neither the token nor the idempotency key is written to the log" | Add the authorization header to the request log line | Killed |

Tally: of the 10 named tests, 9 killed their mutation and 1 survived (#7). Test #1 survived its first mutation (dropping modifier deltas, which its fixture does not use) and was killed by the second (price plus one cent), so it guards the price but not the modifier arithmetic, which `PricesAreComputedFromTheCatalogInIntegerCents` guards. I first left mutation 4 out of the run by mistake and ran it afterwards; its result stands.

**What the survivors mean**
- **#7:** `JwtValidationTests` builds its own `TokenValidationParameters` (with `ValidateIssuer = true`) and calls the framework's `JwtSecurityTokenHandler`. It tests the library, not `AuthServiceExtensions`, so turning issuer validation off in our code goes unnoticed by this test. Another test or the integration tests (`ServiceAuthIntegrationTests`, `MockOidcMiddlewareIntegrationTests`) may cover it; I did not check whether they would kill this mutation, because the sample ran only the named class. Register candidate: a wrong-issuer test through the real service pipeline.
- **#1:** the test name promises more than its fixture proves for modifiers; the modifier arithmetic is guarded by `PricesAreComputedFromTheCatalogInIntegerCents`, which did fail.

This supports the claim "a test is not evidence until it can fail" for eight of nine here, and shows its limit: a test can pass review and still not exercise the code it names (#7). Ten is too few for a rate.
