# Method

> **Status:** Current · created 2026-10-30

How work is specified, tracked and recorded in this repository. Each file says what this project does; none depends on another repository.

| File | Contents |
|---|---|
| `status-and-supersession.md` | Status vocabularies (work items, documents, ADRs, register) and the note types allowed on historical records |
| `glossary.md` | Process terms (outcome note, gate, slice, packet) |
| `work-item-template.md` | The shape of a work-item spec |
| `register-item-template.md` | The shape and status values of an open-items register item |
| `ai-collaboration.md` | How AI assistants are used here, the handoff rules, what went wrong and which control caught it |
| `context-completeness.md` | The proactive discipline: giving a delegate what they need before they start, across plan, delegate, implement, review and refine |
| `decision-checklists.md` | The technology and business questions to answer once, early, with how they were answered here |
| `rule-authoring.md` | How rules are written (hard invariant or guided default, and how each is verified), and the main rules classified |
| `lessons.md` | What was learned from doing the work, with the evidence and what changed |
| `surprise-rule.md` | The reactive response, in any phase, when something was missed |
| `document-lifecycles.md` | Every kind of document, how its status is kept and how it ends (draft; grows as the clean-up proceeds) |

The lessons and the decision checklists are written (`lessons.md`, `decision-checklists.md`); new ones are added as they are learned.
